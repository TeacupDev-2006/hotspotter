## 一、项目是做什么的

我是一名大学生，想第一时间获取热点信息（比如 AI 大模型的更新），但不想手动刷新闻。于是做了一个自动化系统：

**添加监控关键词 → 系统自动从多个信息源采集 → AI 判断相关性和真伪 → 实时推送到网页和邮箱**

两大核心功能：
1. **关键词监控**：输入关键词（如"GPT-5"），相关新闻/推文出现时自动捕获并通知
2. **定时热点搜集**：每 30 分钟自动扫描一轮，热点情报持续可见

两条产品形态：
- **响应式 Web 网页**（情报雷达站风格）
- **Agent Skill**（让 Claude/ZCode 等 AI 助手直接帮你查热点）

## 二、技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Node.js 20+ / Express | 前后端同语言，单进程跑完所有事 |
| 数据库 | SQLite（Node 内置 node:sqlite） | 零原生依赖，单文件，Windows 免编译 |
| 定时任务 | node-cron + setInterval | 每 30 分钟扫描 + 每日 08:00/20:00 邮件简报 |
| 前端 | 原生 HTML/CSS/JS + Canvas | 轻量迅捷，不引框架 |
| 实时推送 | SSE（Server-Sent Events） | 比 WebSocket 简单，单向推送够用 |
| AI | OpenRouter API | 一套 key 通所有模型，随时切换 |
| 邮件 | nodemailer + QQ 邮箱 SMTP | 免费可靠 |

**信息源设计（多源互备，单源故障自动降级）：**

| 源 | 方式 | 费用 |
|---|---|---|
| Google News | RSS 搜索 | 免费（国内需代理） |
| Bing News | RSS 搜索 | 免费（国内服务器被重定向，见排障记录） |
| 今日头条 | 搜索页内嵌 JSON 解析 | 免费（国内直连可用） |
| X / Twitter | twitterapi.io 第三方 API | 免费额度 $0.1（约600条），之后 $5/3万条 |

**AI 判断逻辑（这是项目灵魂）：**
- 相关性过滤：广告、卖号、刷屏内容直接丢弃
- 跨语言聚类：中日英文报道同一事件的合并为一个"情报"
- 真伪三档：`已验证`（≥2个独立可靠来源交叉印证）/ `待印证`（单一来源）/ `存疑`（营销号、夸大、无信源）
- 置信度 0-100 + 热度 0-100（AI 评分 × Twitter 互动数据加权）+ 中文摘要

## 三、开发过程

### 1. 项目骨架（约 10 分钟）

```
npm init → 安装 express / node-cron / nodemailer / dotenv
.env 存密钥（gitignore 排除！）
server/ 后端 + public/ 前端 + skill/ AI技能
```

### 2. 采集层：一路踩坑换来了三路可用源

**坑 1：DuckDuckGo 被风控。** 最初计划用 DDG 的 HTML 版做免费网页搜索，实测返回 202 状态码 + 反爬验证页（lite 版也是）。→ **换成 Bing News RSS**（`format=RSS` 是官方输出）。

**坑 2：Node 不走系统代理。** 本机直连 Google 报 `fetch failed`，但系统明明挂着 Clash。原因是 Node 的 fetch 默认不读系统代理。→ 安装 `undici` 包，代码里显式用 `ProxyAgent` 走 `http://127.0.0.1:7897`。

**坑 3：代理会中途下线。** 开发中途 Clash 关了一次，所有请求全挂。→ 给 `fetchWithTimeout` 加了**代理故障自动回退直连**（检测到连接代理被拒就改直连重试），从此代理开不开都能跑。

### 3. AI 层：三个问题

- **402 余额不足**：OpenRouter 账户没充值，付费模型用不了 → 换**免费模型** `nvidia/nemotron-3-super-120b-a12b:free`（实测判断质量很好）
- **JSON 输出被截断**：分析 24 条内容时 AI 输出超长被截断 → 分批（每批≤14条）+ 提高 token 上限 + 写了截断 JSON 自动修复函数（按括号栈补全）
- **Node 22 与 Node 24 行为不一致**：这个坑在部署服务器时才爆，见后文排障记录

AI 判断质量实测（真实案例）：
> "Anthropic 为 Claude 文本添加电子水印" → ✅已验证 90 分（CNET Japan、ITmedia、Forbes Japan 三源交叉）
> "华科大×华为无需大语言模型实现 VLA" → ⚠️存疑 20 分（来源是 CSDN 个人博客）

### 4. 前端：情报雷达站

为了避免"暗色+荧光绿"的千篇一律黑客风，视觉定位调整为**业余无线电监测站的磷光雷达屏**：墨绿底、余晖质感、琥珀指示灯、等宽仪表数字。

签名元素是**有真实信息含量的值班雷达**：
- 每个监控关键词是雷达上一个位置稳定的信号点
- 扫描线扫过时信号点亮起余晖
- 捕获新情报时对应信号爆发脉冲环
- **点击雷达盘 = 立即扫描**（后来加的，省去找按钮）
- 代理离线自动降级的源会在"接收机"面板显示"无信号"

浏览器 GUI 黑盒测试了 8 个测试点（桌面 1280px + 移动 390px 视口截图验证）：页面加载、增删关键词、手动扫描、过滤、通知抽屉、空输入边界、通知链路、雷达点击，全部通过。

### 5. 通知与调度

- 站内通知中心 + SSE 实时推送 + 浏览器系统通知
- QQ 邮箱：在网页版设置里开 SMTP 服务拿**授权码**（不是QQ密码！），高置信事件即时告警 + 每日两封简报
- 每次服务重启的首次扫描静默（不打扰），只有新扫描产出才通知

### 6. Agent Skill（二期）

`skill/hotspotter/` 目录 + SKILL.md（触发词描述）+ CLI 脚本，复用后端的采集和 AI 模块：

```bash
node skill/hotspotter/scripts/hotspot.js watch "GPT-5" --hours 24  # 即时监控
node skill/hotspotter/scripts/hotspot.js brief                     # 今日简报
```

与网页**共享同一个数据库**——AI 助手采集的成果网页上也能看到。

## 四、上传 GitHub

1. `.gitignore` 排除：`.env`（密钥）、`*.db`（数据）、`node_modules/`、截图目录
2. `git init -b main` → `git add -A` → 首次提交前**逐一核对没有密钥文件被追踪**（`git ls-files | grep .env` 确认）
3. 在 github.com/new 建空仓库（**不勾选**任何初始化选项，避免冲突）
4. push 时国内网络被重置（`Connection was reset`）→ 给仓库配置代理：`git config http.proxy http://127.0.0.1:7897`
5. README 标注：大学生个人 AI 项目、作者分工（我负责需求验收 + AI 负责实现）、灵感参考来源

> 安全习惯：API 密钥只在 `.env` 和对话里出现过，永远不进 Git；对话中暴露过的密钥建议定期轮换。

## 五、阿里云部署

### 1. 准备

- 买了一台杭州的 ECS（CentOS Stream 9，2C2G，¥112/年学生价）
- 控制台**安全组放行 3210 端口**（网页打不开九成是这个没开）
- 服务器上：`git clone`（国内拉 GitHub 慢可用镜像或本机打包上传）→ `cp .env.example .env` 填密钥（**PROXY_URL 必须留空**，服务器上没有本地代理）→ `bash deploy.sh` 一键部署（自动装 Node 20 + pm2 守护 + 开机自启）

### 2. 安装阿里云 workbench CLI

官方 PowerShell 一键脚本误判权限装到 Program Files 失败 → 手动下载二进制装到用户目录 + 配 PATH。配置凭证时发现：
- CLI 的 `config set` 不支持写密钥字段，交互式又无法自动化 → 从二进制里挖出配置文件的真实 schema，直接写 `~/.workbench/config.json`
- RAM 用户必须授权：先加 `AliyunECSFullAccess`（能列出实例），**还要加自定义策略 `ecs-workbench:*`**（远程登录是独立服务）
- **致命 bug**：CLI v1.0.0 在 Windows 上远程执行命令必挂（命名管道地址用了 TCP 拨号）→ 放弃它，改用**阿里云云助手 OpenAPI**（`@alicloud/ecs20140526` SDK + RunCommand），自己写了个远程执行脚本，从此稳定

### 3. 服务器排障实录（最有价值的部分）

部署完成后体检发现：网页正常但**采集全挂**（所有源报 `null == true`，0 条入库）。

**排查过程：**
1. 加了一个 `/api/diag` 诊断端点（回报 Node 版本、代理配置、各源连通性）——因为远程命令通道坏了，先让服务器自己汇报
2. diag 显示：代理没配（排除）、Bing/OpenRouter/twitterapi 全挂、百度却正常 → 锁定不是出网问题
3. 在服务器上裸调 undici fetch 测百度——**一切正常**！唯独走我封装的 `fetchWithTimeout` 就挂
4. **根因**：无代理时我也显式传了 `dispatcher: undefined`，undici 8 在 Node 22 上会因此抛错（我本地 Node 24 没这问题，完美隐藏）
5. 修复：只在配置了代理时才传 `dispatcher` 字段 → 部署后 Bing/OpenRouter 立即恢复 200

**第二关：Bing 在国内服务器采到 0 条。**
diag 显示 Bing 200 连通，但采集器空手而归。用 curl 看真实响应：`www.bing.com` 被 302 到 `cn.bing.com`（中国区必应），而中国区**禁用了 RSS 输出**，返回的是 HTML 页面。试了 `cc=us`、`mkt=en-US`、`ensearch=1` 全部无效（按 IP 强制跳转）。
→ **方案：新增今日头条采集器**。实测发现 `so.toutiao.com` 搜索页 HTML 里内嵌结构化 JSON（含 title/summary/source/跳转链接），写解析器提取，国内服务器直连可用，中文新闻质量很高。

**第三关：twitterapi.io 报 402。** 免费额度 $0.1 被开发联调消耗完了。要么充 $5（约3万条，大半年够用），要么接受现状（头条等其他源兜底）。

**第四关：Google 被墙。** 服务器直连超时，属预期——多源降级设计的意义就在这，核心功能不受影响。

**修复后全链路验证：** 49 条采集 → AI 过滤 7 条噪音 → 16 个新事件（含"月之暗面 Kimi K3 开源"等真实热点），pm2 稳定运行。

### 4. 代码同步方案

国内服务器 `git pull` GitHub 不通（镜像也时好时坏）→ 用云助手 API + base64 直接传输改动文件（大文件自动分块，云助手单条命令上限 16KB），服务器上 commit 保持 git 状态对齐。

## 六、功能迭代

每个功能都走"本地开发 → 本地 GUI 实测 → 分块部署服务器 → 公网验证 → push GitHub"的流程。

## 八、经验总结

1. **密钥安全**：`.env` 永远不进 Git；对话里出现过的 key 记得轮换
2. **环境差异是最大坑源**：本地 Windows + Node 24 vs 服务器 Linux + Node 22，同样的代码不同表现。诊断端点（/api/diag）这种"让服务器自己汇报"的手段极其有效
3. **多源冗余不是过度设计**：Google 被墙、Bing 被重定向、twitter 额度尽、DDG 被风控——四源里三个在服务器上出过问题，但系统始终没停摆
4. **官方工具也会有 bug**：workbench CLI 的 Windows 管道 bug、安装脚本的权限误判。绕过去（云助手 API 直连）比死磕更快
5. **AI 结对编程的真实节奏**：我做需求和验收决策（技术栈、视觉风格、通知渠道都是人工确认过的），AI 负责实现和排障，遇到岔路（比如换信息源）先给方案再动手
